## 二、技术点三句话

### 2.1 答案可靠性保障

| 要素 | 内容 |
|------|------|
| **解决了什么问题** | 网络波动时答案提交易丢失，成功率仅 75% |
| **核心实现思路** | 三层保障：① 作答时同步写 LocalStorage ② 网络异常等待恢复 ③ 指数退避重试 (1s→2s→4s→8s) |
| **效果数据** | 成功率 75% → 95%（分母：灰度期间 1000+ 次提交统计） |

### 2.2 切片上传断点续传

| 要素 | 内容 |
|------|------|
| **解决了什么问题** | 口语音频文件大（10MB+），弱网上传易中断导致前功尽弃 |
| **核心实现思路** | 1MB 分片 + 并发 3 切片 + 进度存 LocalStorage + 中断后跳过已上传切片 |
| **效果数据** | "必须重来"变为"断点可续"（分母：包含音频的考试中 8% 发生过中断） |

### 2.3 HTTP Range 流式播放

| 要素 | 内容 |
|------|------|
| **解决了什么问题** | 音频全量加载慢，考试等待时间长，体验差 |
| **核心实现思路** | HTML5 Audio + Range 请求探测 + 预加载策略，边缓冲边播放 |
| **效果数据** | 卡顿率降低 40%（分母：`timeupdate` 间隔 > 500ms 的占比，基线 2 周全量数据） |

### 2.4 策略模式题型架构

| 要素 | 内容 |

## 三、踩坑故事

### 踩坑 1：断点续传刷新后 File 对象丢失

**背景：** 实现切片上传时，刷新页面后 `File` 对象无法从 LocalStorage 恢复

**问题现象：**
- 上传到 60% 时刷新页面
- 重新进入时读取了 LocalStorage 进度，但 File 引用已变化
- 切片哈希校验失败，服务器拒绝上传

**解决：**
```
原来：File 对象 → 直接记录（无法序列化）
现在：File → (fileName + fileSize + lastModified) 作为 key → 切片哈希校验

恢复：重新选择文件 → 匹配本地进度 → 验证切片哈希 → 断点续传
```

**关键代码：**
```typescript
const fileKey = `${file.name}_${file.size}_${file.lastModified}`;
const savedState = getLocalUploadState(fileKey);
if (savedState && validateChunks(file, savedState.chunks)) {
  // 可以断点续传
}
```

**经验：** 不要试图序列化 File/Blob，用文件元数据特征作为 key。

### 踩坑 2：拖拽题型与文本选中冲突

**背景：** 拖拽的 `mousedown`/`mousemove` 事件与浏览器文本选中冲突

**问题现象：** 鼠标在拖拽区域移动时，无法选中任何文本

**解决思路演变：**
```
方案 A：禁用文本选中 (user-select: none) → 考生无法复制题目 ❌
方案 B：拖拽时按住修饰键 → 改变用户习惯 ❌
方案 C：阈值判断意图 → 记录 mousedown 位置，> 5px 才判定为拖拽 ✅
```

**关键代码：**
```typescript
let dragStartPos = { x: 0, y: 0 };
element.addEventListener('mousemove', (e) => {
  const distance = Math.hypot(e.clientX - dragStartPos.x, e.clientY - dragStartPos.y);
  if (distance > 5) { isDragIntent = true; /* 开始拖拽 */ }
});
```

**经验：** 交互冲突时，用阈值区分用户意图，不要直接禁用浏览器行为。

### 踩坑 3：MobX 响应式"幽灵数据"

**背景：** API 返回数据，stores 有数据，但 UI 不更新

**排查：**
1. 是否在 `observer` 组件内 → 是
2. 是否调用了 MobX action → 是
3. 发现问题：直接赋值 `this.exams = newArray` 丢失响应式追踪

**解决：**
```typescript
// ❌ 直接赋值丢失响应式追踪
this.currentExam = newArray;

// ✅ 操作原数组
this.currentExam.length = 0;
this.currentExam.push(...newArray);
```

**经验：** MobX 中直接替换数组引用会破坏响应式，必须操作原数组。

## 六、高频面试问题

### Q1: 如何保证答案不丢失？

**参考答案：**
> 三层保障：① 作答时同时写入 LocalStorage ② 网络异常时自动重试 ③ 使用指数退避算法避免拥塞。离线答案持久化，网络恢复后自动上传，成功率从 75% 提升到 95%。

### Q2: 弱网下大文件如何上传？

**参考答案：**
> 采用切片上传 + 断点续传。将文件按 1MB 分片，并发上传 3 个切片，每个切片完成后记录进度到 LocalStorage。中断后恢复时读取本地进度，跳过已上传切片，继续上传剩余部分。

### Q3: 多种题型如何设计？

**参考答案：**
> 使用策略模式。将每种题型封装为独立组件，通过 type 字段动态选择。新增题型只需实现组件并注册到策略表，接入成本从 2 人天降至 0.5 人天。

### Q4: 音频播放卡顿如何优化？

**参考答案：**
> 基于 HTTP Range 实现流式预加载。使用 HTML5 Audio 的 preload + Range 请求，边缓冲边播放。配合 Promise 缓存避免重复探测，卡顿率降低 40%。

### Q5: 考试系统最重要的是什么？

**参考答案：**
> **数据可靠性**。考试涉及考生利益，答案不能丢失。对比功能炫技，我们更关注：离线缓存、网络探测、指数退避、事务性提交。

### Q6: 页面刷新后状态如何恢复？

**参考答案：**
> 使用 MobX 的 `reaction()` 监听状态变化，自动同步到 LocalStorage。页面加载时从 LocalStorage 读取并恢复数据。恢复时间 < 1s，数据完整率 100%。
